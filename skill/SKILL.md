# AQUA Project Skill

Use this skill when the user asks to create, inspect, validate, or extend a TypeScript agent harness project generated by AQUA.

This is an installable user-facing Skill. It is intentionally stored outside `src/` so users and agent runtimes can install or copy it without treating it as part of AQUA's TypeScript source workspace.

Do not present a generated project as a finished intelligent application. A newly generated project must fail honestly with `MODEL_PROVIDER_NOT_CONFIGURED` until the user implements or injects a real model provider.

## Contract

An AQUA project is valid only when it contains `.aqua/project.json` and that manifest matches the generated files. Treat `.aqua/project.json` as the source of truth shared by CLI, Skill, and future harness adapters.

## Required behavior

1. Ask for the target directory if the user did not specify one.
2. Prefer the local `aqua` CLI from this repository when available.
3. Create new projects with:

   ```bash
   aqua create <target-dir> --preset <minimal|research-assistant|coding-agent> --harness <standalone|codex|opencode|claude-code>
   ```

4. After creation or modification, run:

   ```bash
   aqua validate <target-dir>
   aqua doctor <target-dir>
   ```

5. Verify the generated project with:

   ```bash
   pnpm run typecheck
   pnpm test
   pnpm run smoke
   ```

6. Run the generated application once. Treat `MODEL_PROVIDER_NOT_CONFIGURED` as the correct first-run result unless the user already supplied a real provider.
7. Do not claim parallel agent dispatch unless the target harness has a verified adapter. If unavailable, state `CAPABILITY_UNAVAILABLE: parallelAgents`.
8. Do not add hidden LLM clients, credentials, background services, fake model providers, or fake protocol support.
9. Keep harness base code generic. Put application-specific behavior in agents, tools, workflows, or presets.

## Modification rules

- Update `.aqua/project.json` and source files together.
- Keep public seams stable: model provider, runner, workflow, agent, tool, trace, artifact store.
- Add tests at public seams only: CLI behavior and generated project behavior.
- Run TypeScript typecheck before reporting success.
- Never replace a failing provider seam with a placeholder echo response.

## Preset guidance

- `minimal`: use for an empty but runnable base.
- `research-assistant`: use for evidence, literature, document, or web-analysis projects.
- `coding-agent`: use for code-writing, patching, verification, and review workflows.
